# DCA 機器人使用手冊（Dollar-Cost Averaging Bot）

> 版本：v1（Phase 7 交付）｜日期：2026-08-26
> 對應計畫：`docs/dca_bot_implementation_plan_zh-TW.md`
> 適用範圍：Web 總控台「DCA 機器人」與「建立 DCA」分頁
> **重要**：本版本**不開啟 LIVE 實盤**。`GRID_LIVE_TRADING_ENABLED` 維持關閉，所有操作請在 PAPER 模式進行。

---

## 1. 什麼是 DCA 機器人

DCA（定期定額 / 攤平成本）機器人與網格策略的最大差異：

| 面向 | 網格 (Grid) | DCA |
|---|---|---|
| 啟動後行為 | 立即在區間鋪滿雙向掛單 | **啟動後不掛任何單**，進入「監控中」（`armed`） |
| 進場 | 啟動即掛 | 僅在**入場條件成立**後才下基礎單 + 安全單 |
| 訂單結構 | 對稱網格層級 | 單向遞減（做多）/遞增（做空）**安全單階梯** |
| 獲利方式 | 區間往返套利 | 攤平成本後，以**單一止盈單**一次性了結 |
| 生命週期 | 長期常駐 | **循環**：監控 → 觸發 → 攤平 → 止盈 → 冷卻 → 回到監控 |

**「監控中不掛單」是本機器人最重要的性質**：機器人處於 `armed` 時，交易所端對這台機器人的掛單數 = **0 筆**。UI 仍會顯示這台機器人與「監控中」狀態，但不存在任何真實掛單，也不占用任何資金。只有入場條件成立後才會真正下單。

## 2. 狀態機（徽章語意）

| 徽章 | 狀態 | 交易所掛單 | 持倉 | 說明 |
|---|---|---|---|---|
| 🟡 監控中 | `armed` | **0 筆** | 0 | 評估入場條件，不下任何單 |
| 🔵 進場中 | `triggering` | 0→1 | 0→有 | 條件成立，正在下基礎單 |
| 🟢 攤平中 | `averaging` | 安全單 + **恰好 1 筆止盈** | 有 | 主要運行狀態 |
| ⚪ 本輪完成 | `completed` | 0 | 0 | 止盈或止損成交 |
| 🕐 冷卻中 | `cooling` | 0 | 0 | 循環模式過渡（可能換方向） |
| 🟠 停止中 | `stopping` | 撤單中 | 不變 | 命令已受理 |
| ⚫ 已停止 | `stopped` | 0 | **預設不平倉** | |
| 🔴 失敗 | `failed` | 盡力撤單 | 不變 | 需人工介入 |
| 🟣 降級 | `degraded` | — | 有 | 止盈單暫時無法重掛，持續重試（期間不回報正常） |

> **循環**：`completed → cooling → armed` 是預設路徑。冷卻期間解除方向鎖定，冷卻結束後重新同時評估多空，因此第 2 輪可能是相反方向。只有 `max_cycles` 達成或你主動停止才會進入 `stopped`。

## 3. 建立一台 DCA 機器人（4 步精靈）

側邊欄點「建立 DCA」，依序完成 4 步；右側 Summary 的所有數字都由後端試算（`POST /api/v1/dca/preview`），前端不自行計算。

### Step 1 — General（交易對與帳戶）
- 選交易所與交易對；系統自動抓取精度與最小名目額（`market/info`）。找不到交易對會顯示明確錯誤，未確認前無法前進。
- 方向：`做多 (long)` / `做空 (short)` / `雙向 (both)`。
  - **雙向**＝同一時刻只執行一個方向（先觸發者獨佔本輪）；所需資金 = max(多, 空)，**不是**兩組相加。
- 帳戶模式：本版本固定 **PAPER**。

### Step 2 — Entry（入場條件）
- **立即入場（immediate）**：啟動後馬上下基礎單，不看指標。
- **指標入場（indicator）**：符合技術指標才進場。
  - 組合邏輯：`全部 (AND)` / `任一 (OR)`。
  - 共用參數：時框（所有指標共用，預設 `15m`）、取樣根數（100–500，預設 300）、價格來源（`close`/`hlc3`/`ohlc4`）、確認 K 棒（1–5，連續成立幾根已收線 K 棒才觸發，抗插針）。
  - 四種指標可獨立啟用，詳見 §5。

### Step 3 — DCA（階梯參數）
| 參數 | 概念圖對應 | 說明 |
|---|---|---|
| 每單金額 `base_order_amount` | Amount per trade | 基礎單名目（USD 或幣） |
| Max DCA orders `max_safety_orders` | Max DCA orders | 安全單上限（1–50） |
| Price deviation `price_deviation_percent` | Price deviation | 第一張安全單的價格偏移% |
| Price dev. multiplier `price_deviation_multiplier` | Price dev. multiplier | 偏移的等比倍數（≥1） |
| Order size multiplier `order_size_multiplier` | Order size multiplier | 每張安全單金額的等比倍數（≥1） |
| Take profit target `take_profit_percent` | Take profit target (%) | 以攤平均價為基準的止盈% |
| 止損 `stop_loss_percent` | — | 留空停用；填入以最終均價為基準 |
| 活躍窗口 `active_safety_orders_window` | — | 同時掛在交易所的安全單張數上限（預設 5） |

### Step 4 — Summary（回顧與送出）
- 顯示所需資金、最大覆蓋跌幅、最終均價、最終止盈價與完整階梯表——全部來自後端試算。
- 建立成功後預設**不自動啟動**（`auto_start=false`）；回到 DCA 大盤再手動啟動。

## 4. 階梯數學（機器人如何攤平）

設入場價 `E`、`b = price_deviation_percent/100`、`m = price_deviation_multiplier`、`s = order_size_multiplier`、`N = max_safety_orders`、`V₀ = 每單金額`。

**每張安全單的偏移**（第 i 張，i = 1..N）：
```
dev_i = b × m^(i-1)
```

**安全單價格**（做多；做空把 `(1 − dev)` 換成 `(1 + dev)`）：
```
dca_mode = order    : P_i = P_{i-1} × (1 − dev_i)   , P_0 = E
dca_mode = position : P_i = avg_{i-1} × (1 − dev_i) , avg_0 = E
```

**下單量**：
```
averaging_method = fixed_value : V_i = V₀ × s^i     ; Q_i = V_i / P_i
averaging_method = fixed_coin  : Q_i = (V₀/E) × s^i ; V_i = Q_i × P_i
```

**均價 / 止盈價 / 所需資金 / 最大覆蓋跌幅**：
```
avg_k         = Σ V_j / Σ Q_j                （j = 0..k）
take_profit_k = avg_k × (1 + tp/100)         （做空為 × (1 − tp/100)）
required      = Σ V_j                         （j = 0..N）
max_drawdown% = (E − P_N) / E × 100           （做空為 (P_N − E) / E × 100）
```

**範例（向量 A）**：`E=2500, b=0.8%, m=1.2, s=1.0, N=20, V₀=20 USD, order + fixed_value`
- 第 1 張偏移 `0.80%`、第 20 張偏移 `25.56%`
- 第 20 張價格 `496.71`、最終均價 `1468.99`、止盈價（tp=1%）`1483.68`
- 所需資金 `420.00 USD`、最大覆蓋跌幅 `80.13%`

> 每張安全單成交後，機器人會**自動重掛止盈單**到新的攤平均價（事件時間線會出現「止盈重掛」）。因此止盈永遠貼著當前均價。

## 5. 四種入場指標（含預設值）

四種指標共用同一條 K 線管線與同一時框。開啟指標時欄位會預填以下凍結預設值，皆可自行調整。

### 5.1 RSI（相對強弱指標）
| 參數 | 預設 | 範圍 |
|---|---|---|
| `period` | 14 | 2–100 |
| `oversold`（做多線） | 30 | 1–50 |
| `overbought`（做空線） | 70 | 50–99 |
| `condition` | `level` | `level` / `cross_in` / `cross_out` |

- `level`：`RSI ≤ oversold`（多）/ `RSI ≥ overbought`（空），在超賣/超買區**持續**為真。
- `cross_in`：由上向下**穿越**超賣線（多）/由下向上穿越超買線（空），只在穿越當根為真。
- `cross_out`：穿回超賣/超買線（反彈/回落確認）。
- 搭配循環模式（`repeat_after_take_profit=true`）建議用 `cross_in`，避免同段行情反覆立即進場。

### 5.2 MACD
| 參數 | 預設 | 範圍 |
|---|---|---|
| `fast` | 12 | 2–100 |
| `slow` | 26 | 3–200（須 > fast） |
| `signal` | 9 | 2–50 |
| `condition` | `cross` | `cross` / `hist_sign` / `zero_cross` |

- `cross`：柱體由 ≤0 轉 >0（黃金交叉，多）/ 由 ≥0 轉 <0（死亡交叉，空）。
- `hist_sign`：柱體 >0（多）/ <0（空），持續狀態。
- `zero_cross`：MACD 線穿越零軸。

### 5.3 Bollinger Bands（布林通道）
| 參數 | 預設 | 範圍 |
|---|---|---|
| `period` | 20 | 2–200 |
| `std_dev` | 2.0 | 0.5–5.0 |
| `condition` | `touch` | `touch` / `break` / `return` |

- 使用**母體標準差**（除以 n），與 TradingView 一致。
- `touch`：收盤 ≤ 下軌（多）/ ≥ 上軌（空）。
- `break`：當根跌破下軌 / 突破上軌（穿越當下）。
- `return`：跌破後收回下軌上方 / 突破後收回上軌下方。

### 5.4 Price Change（區間漲跌幅）
| 參數 | 預設 | 範圍 |
|---|---|---|
| `lookback_bars` | 24 | 1–500 |
| `long_threshold_percent`（多） | -3.0 | −100 ~ +100 |
| `short_threshold_percent`（空） | +3.0 | −100 ~ +100 |

- 比較「當前收盤」與「往回第 `lookback_bars` 根收盤」的漲跌幅。
- 做多：跌幅 ≤ 長門檻（如 ≤ −3%）；做空：漲幅 ≥ 空門檻（如 ≥ +3%）。
- 精靈會顯示換算，例如「24 根 × 15m = 6 小時」。

> **即時值**：建立精靈的指標面板顯示各指標當前值與「成立✓/不成立✗」。資料不足時顯示「資料不足」，**不會**用 0 偽裝。

## 6. 詳情工作台（六分頁）

在 DCA 大盤點任一機器人卡片，進入詳情工作台。頂部 KPI（淨盈虧、持倉、均價、安全單/循環、當前價、手續費）與大盤卡片同一讀模型，數值一致。

| 分頁 | 內容 |
|---|---|
| **階梯** | 完整安全單表：層級、角色、偏移%、價格、數量、名目、狀態（已成交/掛單中/未觸及/略過）；標出當前價列與均價線。 |
| **訂單** | 當前交易所掛單（含角色標記）。**監控中時應為空**。 |
| **成交** | 歷史成交，含手續費與成交後累積均價；超過 50 筆自動分頁。 |
| **事件** | 生命週期事件時間線（觸發、止盈重掛、急跌重對齊、曝險上限、止損、錯誤）。 |
| **指標** | 入場指標設定與參數摘要。 |
| **設定** | 完整設定唯讀檢視 + YAML 原文。 |

## 7. 操作與生命週期

- **啟動**：把機器人切到「運行」。啟動成功只代表命令已受理（`pending_engine`），要等引擎心跳才顯示為運行中，且首先進入「監控中」。
- **停止**：撤銷所有掛單，**預設不平倉**（現有部位保留）。
- **刪除**：只允許已停止的機器人；YAML 會移到 `config/dca/archived/` 歸檔（不是直接刪）、runtime 快照清除。
- 所有 create / start / stop / delete 都會寫入審計日誌（`GET /api/v1/system/audit`）。

## 8. 風險說明

- **DCA 不是穩賺**：攤平會在下跌中不斷加碼。若價格持續單邊下跌且未觸及止盈，部位與浮虧會擴大到 `所需資金 (required)` 上界。務必用 Summary 的「所需資金」與「最大覆蓋跌幅」評估你能承受的極端情境。
- **請設定風控**：可用 `stop_loss_percent`（止損）與 `max_position_notional`（硬性曝險上限）限制最壞情況。
- **急跌穿透**：單根 K 棒可能穿透多層安全單價位。機器人會以現價重新對齊窗口並補掛，事件時間線出現「急跌重對齊」提醒。
- **監控中不占資金，但一旦觸發即開始投入**：確認入場條件符合你的預期再啟動。
- **本版本僅 PAPER**：不要在此版本嘗試開啟 LIVE。LIVE 放行需另行完成稽核標準 §2 的最低條件。

## 9. 常見問題

**Q：為什麼啟動後「訂單」是空的？**
A：這是設計。監控中（`armed`）不掛任何單，等入場條件成立才下基礎單與安全單。

**Q：止盈價為什麼會變動？**
A：每張安全單成交後均價下移（做多），機器人自動把止盈單重掛到新均價，讓止盈永遠貼著當前均價。

**Q：雙向模式會同時做多又做空嗎？**
A：不會。同一時刻只有一個方向持倉，先觸發者獨佔本輪；所需資金以較大一側計。

**Q：停止會賣掉我的部位嗎？**
A：不會，停止只撤單、不平倉。若要平倉請自行處理或設定止損。

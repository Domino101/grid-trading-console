## 1. 倉位對照表（核心決策）

| 狀態 | 保守版（建議先上） | 積極版（軟閘門） | 樣本內年化 | 樣本外年化 |
|---|---|---|---|---|
| **pts = 0** 風險關閉 | **0×（平倉）** | 0.35× | +4.2% | −42.8% |
| **pts = 1** | 1.0× | 1.0× | +37.8% | +20.5% |
| **pts = 2**（三者中恰有兩項），且資金費率百分位 ≥ 45 | 1.0× | **1.15×**（上限 1.2×） | +94.5% | +75.1% |
| pts = 2 但資金費率百分位 < 45（僅趨勢＋廣度） | 1.0× | 1.0× | — | 歷史明顯較弱（−3.6% ~ −18.3%/年） |
| **pts = 3** 過熱 | 1.0× | 1.0× | −2.7% | +45.6% |

**兩版績效（v2 參數、7 日換倉、K=5）**

| 版本 | 全期總報酬 | 年化 | Sharpe | 最大回撤 | 樣本外 |
|---|---|---|---|---|---|
| 保守版（0 或 1.0） | +154.1% | 18.8% | 1.41 | −15.3% | 25.1% / Sharpe 1.94 |
| 積極版（0.35 / 1.0 / 1.15） | **+202.4%** | 21.7% | 1.35 | **−13.9%** | **25.9%** / Sharpe 1.85 |

> 積極版報酬高約 48pp、回撤略小，但 Sharpe 略低且依賴兩處參數選擇（0.35、1.15）→ **建議先上保守版，紙上驗證 2–3 個月後再評估切換。**
> 若需對照 4 級映射 {0:0.35, 1:1.0, 2:1.2, 3:1.0}，歷史差異僅在 pts=2 的倍數（1.15 vs 1.2）→ 影響約 ±2pp 年化，**建議以 1.15× 為預設、1.2× 為硬上限**。

## 2. 加倉時機（Increase）

所有條件必須同時滿足：

1. **`pts == 2`**（趨勢、廣度、資金費率三者中恰有兩項為正）。
2. **市場資金費率百分位 45–80**：≥ 45（市場願意付費）；> 80 視為擁擠、不加碼。
   * 若 pts=2 是靠「趨勢＋廣度」而資金費率百分位 < 45 → **維持 1.0×，不加碼**（見第 1 節說明）。
3. **不是 pts=3**（三者全滿 = 過熱；樣本內 −2.7%）。
4. **上一週實際成本（手續費 + 滑價 + 資金費率）< 0.5% 本金**。
5. **帳戶維持保證金水位 > 40%**（未接近危險區）。
6. **最近 60 日動能與資金費率 IC 皆為正**（因子未失效）。

加倉執行方式：在**下一次排定換倉日**（週四 UTC 00:05）同步提高目標名義至 1.15×（不做盤中臨時加倉，避免與換倉邏輯衝突）。

加倉幅度：**+15%（上限至 1.2×）**；且短邊（空腿）名義不得超過總名義 60%。

## 3. 減倉與平倉時機（Decrease）

| 優先序 | 觸發 | 動作 | 依據 |
|---|---|---|---|
| 1 | `pts` 由 ≥1 轉為 **0** | **立即平倉、停止下單** | OOS Sharpe 0.84 → 1.94 |
| 2 | 累積回撤 ≤ −18% | 全部平倉、停機檢視 | 風控硬底線 |
| 3 | 累積回撤 ≤ −12% | 降至 0.5× | 風控 |
| 4 | BTC 30 日報酬 < −8.3% | 減半（或平倉） | 該情境策略年化 −13.2% |
| 5 | 資金費率百分位 > 90 | 停止加碼；> 95 且 pts ≤ 1 → 減半 | 擁擠保護 |
| 6 | 單週策略回撤 > 6% | 降至 0.5×，回撤收斂後恢復 | 週期風控 |
| 7 | 連續兩週成本 > 1% | 暫停加碼並檢查流動性 | 成本控制 |
| 8 | 換倉日 BTC ≤ −5% | 延後 24 小時（不改變倉位大小） | Sharpe 1.45 |

> 注意：減倉動作只在**排定換倉日**執行（除第 1、2 項為緊急處置，可即時執行）。

## 4. 明確不採用的倉位管理法（實測數據）

| 方法 | 實測全期年化 | 基準 16.9%（無疊加）→ 結論 |
|---|---|---|
| 投資組合波動目標 18/22/25/30% | 16.5 / 16.5 / 19.4 / 18.9% | 無一致增益、與閘門衝突 → 不採用 |
| 回撤節流（−10%/−12%/−15%/−20% → 0.3–0.6×） | 9.4% | 明顯有害（賣在低點） |
| 個幣停損 −12% / −20% | 145.0% / 141.4%（基準 154.1%） | 有害 |
| 個幣停利 +25% | 123.3% | 有害（切斷趨勢） |
| 低分散度縮倉（disp_pct < 20/25/30） | 13.2% / 0.82 | 有害 |
| 反向下單（風險關閉時翻轉） | OOS 14.9% / Sharpe 0.84 | 有害且週轉加倍 |

**原則：風控做在「狀態層」（要不要持有），不要在「個幣層」干預（停損停利）。**

## 5. 倉位計算公式（實作）

```
總名義 equity = 本金 × 槓桿(1.0) × gate_scale(0 / 1.0 / 1.15)
單邊名義     = 總名義 / 2
每檔名義     = 單邊名義 / K        # K = 5
```

* 例：本金 $1,000、pts=2 且**資金費率百分位 ≥ 45**、積極版 → 總名義 $1,150，多空各 $575，每檔 $115。
* 若 pts=2 但資金費率百分位 < 45（如 2026-09-16 的 29）→ `gate_scale = 1.0`（總名義 $1,000、每檔 $100）。
* 每檔名義低於 $5（`min_order_notional`）時跳過該檔（小資金的已知限制）。
* 下單前必須量化（`quantize_quantity`）並遵守交易所最小下單量與精度。

## 6. 檢核表（每次換倉前 30 秒可完成）

- [ ] 今天是排定換倉日（週四 UTC）嗎？
- [ ] `pts` 是多少？（決定 0 / 1.0 / 1.15）
- [ ] 若 `pts=2`：資金費率百分位 ≥ 45 嗎？→ 否則降回 1.0×。
- [ ] 風險關閉？→ 平倉並結束，不需其他步驟。
- [ ] BTC 24 小時 ≤ −5%？→ 延後 24 小時。
- [ ] 恢復後首日？→ 延後 1 日進場。
- [ ] 資金費率百分位 > 90？→ 不加碼。
- [ ] 帳戶維持保證金 > 40%？→ 否則先降為 0.5×。
- [ ] 通過 → 依 §5 公式計算目標部位並送單（先 reduce-only，後開新倉）。

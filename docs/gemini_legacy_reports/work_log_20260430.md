# 2026-04-30 工作日誌：網格交易系統 Binance WebSocket 價格獲取機制修復

## 1. 修復初始化時 `_price_fetch_lock` 未定義問題
- **問題描述**：系統啟動時崩潰，報錯 `'GridEngineImpl' object has no attribute '_price_fetch_lock'`。
- **原因分析**：在 `GridEngineImpl` 的 `get_current_price` 方法中，`_price_fetch_lock` 的初始化代碼被錯誤地寫在了 docstring（註解）裡面。
- **解決方案**：將 `_price_fetch_lock = asyncio.Lock()` 移至 `__init__` 建構子中進行正確的初始化。

## 2. 修復 `ws_only_mode` 下初始化價格獲取崩潰問題
- **問題描述**：啟動時出現錯誤 `❌ 系统错误: WS-only 模式下無價格緩存且WS未更新`。
- **原因分析**：在啟用 `ws_only_mode` 時，系統嚴格禁止調用 REST API。但系統剛啟動時，WebSocket 的第一筆推送尚未到達，此時系統呼叫 `get_current_price()` 會因為沒有緩存而直接崩潰。
- **解決方案**：在 `grid_engine_impl.py` 增加特例判斷，如果當前完全沒有價格緩存（即初始化階段），允許系統破例調用一次 REST API 來獲取初始價格。

## 3. 修復冷門交易對「價格獲取網絡故障」誤判問題
- **問題描述**：交易正常但系統頻繁報錯 `🚨 价格获取网络故障！连续失败15次` 並暫停。
- **原因分析**：
  1. 系統原先使用 Binance 的 `@ticker`（24小時滾動統計）串流來獲取價格。
  2. 幣安的 `@ticker` 只有在該交易對發生**真實成交**時才會推送。對於冷門交易對（如 SOL/USDC），常出現超過 5 秒無人交易的情況。
  3. 網格系統在超過 5 秒未收到價格更新時會判定為獲取失敗，連續多次失敗則誤判為網路故障。
- **解決方案**：
  1. **切換串流類型**：修改 `binance_websocket.py`，將價格訂閱從 `@ticker` 改為 `@bookTicker`（最優掛單簿）。`@bookTicker` 只要買賣盤報價有變動就會推送，頻率極高，徹底解決了長時間無推送的問題。
  2. **數據解析相容**：由於 `@bookTicker` 不包含最新成交價 (`c`)，在 `_handle_ticker_message` 中加入容錯邏輯，若無最新成交價則以 `(買一價 + 賣一價) / 2` 替代。
  3. **放寬故障判定**：在 `grid_engine_impl.py` 中增加了 `ws_healthy` 檢查（60秒內有收到任何訊息即視為健康），避免因為交易對冷門而輕易觸發網路故障暫停。
  4. **調整容錯閾值**：將 `_price_max_failures` 從 5 次提高至 15 次，增強系統對短暫網路波動的容忍度。

## 備註
- 測試過程中發現 `SOL/USDC:USDC` 交易對報錯 `Order's notional must be no smaller than 5`，已提醒使用者這是因為配置檔中的 `order_amount: 0.0429` (約 $3.5) 低於幣安合約 $5 的最小下單金額限制，需由使用者自行調高。

# 網格 / DCA 回測 使用手冊

> 版本：v1（P4 交付）｜日期：2026-09-01
> 對應計畫：`docs/grid_backtest_implementation_plan_zh-TW.md`
> 前置閱讀：`README.md`（帳戶模式與操作語意）
> **重要**：本版本不開啟 LIVE 實盤。`GRID_LIVE_TRADING_ENABLED` 維持關閉；所有回測皆為唯讀，不會下任何真實訂單。

---

## 0. 這個分頁回答什麼問題

左側新增「**網格回測**」分頁，把「策略市場只有短期年化排名」的侷限補齊。

| 策略類型 | 回答的問題 | 核心引擎 |
|---|---|---|
| 網格 | 「這組上下限 / 格數 / 每格金額 / 槓桿，用 $X 初始資金在過去這段行情跑，會不會爆倉／回撤多少？」 | `core/services/grid/backtest/` 資金感知模擬器 |
| DCA 單向 / 雙向 | 「這組 DCA 階梯與指標條件，用 $X 初始資金在過去行情依指標進場，績效與回撤如何？」 | 既有 DCA `DcaCoordinator + DcaOrderExecutor + EntryMonitor`，與實盤同一套決策程式碼 |

> **兩者不是同一套模型。** 網格是**資金感知近似模擬**；DCA 是**與實盤同源的離線回放**（較高保真）。所以兩者的「簡化事項」揭露內容不一樣。

---

## 1. 進入回測分頁

1. 左側選單點「**網格回測**」。
2. 頂部先決定策略類型：**網格回測** 或 **DCA 回測（單向/雙向 + 指標）**。

> 從「策略市場」的排行表格，每一行現在有兩顆按鈕：
> * **一鍵開格**：沿用既有功能，直接帶入建立策略表單。
> * **回測**：把該標的的上下限／格數／間距帶入網格回測頁，並略為預填。

## 2. 網格回測

### 2.1 參數

| 欄位 | 說明 |
|---|---|
| 交易所 / 交易對 | Binance / Lighter / Hyperliquid 與 symbol，例如 `SOL/USDC:USDC` |
| 方向 | 中性 / 做多 / 做空（v1 中性以做多循環近似） |
| Lower / Upper | 價格上下限 |
| 格數 / 間距 | `grid_count` 或 `grid_interval` 二選一 |
| 每格金額 (USD) | 每格名目金額；與「每格佔總本金 %」**可擇一或都填**（都填時以每格金額優先） |
| 每格佔總本金 % | 每格金額佔初始資金比例，例如 10 表示 10% |
| 初始資金 (USD) | 帳戶權益 |
| 槓桿 | 1 / 2 / 3 / 5 / 10 / 15 / 20x（逐倉近似） |
| 時框 | 15m / 30m / 1h / 4h / 1d |
| 區間 | 7 天 / 30 天 / 180 天 / 1 年 / 自訂（UTC） |

### 2.2 三種執行

| 模式 | 輸出 |
|---|---|
| **單次回測** | 總報酬、買入持有對照、Alpha、最大回撤、期末權益、已實現/手續費、完成循環、權益曲線、爆倉/未爆倉 |
| **壓力情境** | 起價與 ±15% / ±30% / ±50% 等線性單向移動後，是否爆倉、最低/期末權益、需追加資金 |
| **參數掃描** | 對「格數 × 每格金額 × 槓桿」多組組合跑回測，列出總報酬、回撤、是否爆倉（預算上限 300000 bar / 20 組） |

### 2.3 讀懂爆倉警示

- **未爆倉**：顯示「未觸發爆倉」與距離清算最接近的餘裕。
- **已爆倉**：顯示爆倉時間，並提示：
  > 若初始資金再增加 **$X**，可避免觸發清算。

這個 `$X` 是以 **isolated 逐倉 + 固定維持保證金率**（預設 0.5%）反推的最低追加資金，用來做**實盤艙位大小控管**參考，不是交易所保證的強平需補金額。

### 2.4 網格回測的限制（務必閱讀）

- 維持保證金 / 清算為**近似**，依交易所規則（資金費率、強平手續費、價格精度）不同而異。
- **不模擬**：部分成交、資金費率、滑價、價格移動（follow）、剝頭皮（scalping）、馬丁（martingale）、止盈/止損。
- NEUTRAL v1 以做多循環近似。
- 歷史績效不代表未來。

## 3. DCA 回測（單向/雙向 + 指標）

### 3.1 來源

| 來源 | 用途 |
|---|---|
| 手動參數（draft） | 用表單建立一份「尚未送出」的 DCA 設定，再回測；與建立機器人走同一套驗證 |
| 既有 DCA bot | 選 `config/dca/*.yaml` 已存在的機器人，直接回測其參數 |

### 3.2 手動參數

| 欄位 | 說明 |
|---|---|
| 方向 | 單向做多 / 單向做空 / **雙向** |
| 基礎單金額 | 進場基礎單 |
| 安全單上限 / 價差% / 價差倍率 / 單量倍率 | 與 DCA 精靈一致 |
| 止盈% / 止損% | 可留空 |
| 槓桿 / 費率 | 逐倉近似 |
| 入場模式 | 立即進場 或 指標進場 |
| 指標 | 勾選 RSI / MACD / Bollinger / Price Change；邏輯 `全部(AND)` 或 `任一(OR)`；指標時框可選 |

### 3.3 指標回測是真實判定

DCA 回測不是「先算一次指標」的假回放：回放路徑使用真實 `DcaCoordinator + DcaOrderExecutor + EntryMonitor`，每個 K 棒時以「只看截至當根的資料」判定指標條件與進場，再撮合階梯與止盈/止損。因此 `direction=both` 與指標模式在回測中就是實際驅動的。

### 3.4 回測結果

- 指標卡：DCA 總報酬、買入持有報酬、Alpha、最大回撤、已實現/手續費、完成輪次/勝率、獲利因子、持倉時間占比。
- 圖表：K 線 + 基礎單 / 安全單 / 止盈 / 止損標記 + 權益曲線。
- 輪次明細：每輪進場/出場、均價、損益、出場原因。
- warnings 全量渲染：不模擬部分成交、未套用交易所最小名目限制、歷史績效不代表未來等。

## 4. 資料來源與狀態

| 狀態 / 來源 | 意思 |
|---|---|
| `live` / `exchange` | 真實歷史 K 線 |
| `stale` | 快取資料超過時效，或只回填部分歷史 |
| `paper` / `paper_synthetic` | 使用 PAPER 合成 K 線，**非真實歷史** |
| `unavailable` | 無法取得足量 K 線；回測會直接報錯，不畫空白結果 |

## 5. 操作建議

1. 先從「策略市場」看短期年化排名做初步篩選。
2. 點「回測」看這組參數在**資金與時間窗口**下的權益曲線與爆倉風險。
3. 以「壓力情境」檢查最差單向移動是否會爆倉，若會，利用「需追加資金」估算所需艙位。
4. 有 DCA 需求時切到 DCA 模式，以指標條件確認進場時機與階梯風險。
5. 記住：任何回測都只是歷史樣本，**不使用真金白銀直接跟單**。

## 6. 常見問題

| 情況 | 說明 |
|---|---|
| 顯示「資金不足」 | 初始資金只夠掛 M 格，實際以 M 格執行；此訊息同時寫入 warnings。您可提高初始資金或降低每格金額。 |
| 顯示「未觸發爆倉」但仍有追加資金值 | 代表歷史最差時點仍未觸發清算，但距離相當近；該值為距離清算門檻的資金緩衝。 |
| DCA 既有 bot 列表沒出現 | 請確認後端 `/api/v1/dca` 快照可用；切換來源後可點「重新載入」。 |
| 一鍵開格與回測帶入的參數差在哪 | 開格寫入建立表單；回測只帶入「回測頁」參數，不會建立或啟動任何策略。 |

## 7. 相關 API

| Endpoint | 方法 | 說明 |
|---|---|---|
| `/api/v1/grid-backtest/run` | POST | 網格單次回測 |
| `/api/v1/grid-backtest/stress` | POST | 網格壓力情境 |
| `/api/v1/grid-backtest/sweep` | POST | 網格參數掃描 |
| `/api/v1/dca/backtest` | POST | 既有 DCA 回測（P4 直接複用） |
| `/api/v1/dca/backtest/sweep` | POST | 既有 DCA 參數掃描 |

所有回測端點皆要求 Bearer token；皆為唯讀，不下真單、不寫 active 設定。

# DCA 圖表與回測 使用手冊

> 版本：v1（Phase C8 交付）｜日期：2026-08-27
> 對應計畫：`docs/dca_chart_backtest_plan_zh-TW.md`
> 前置閱讀：`docs/dca_bot_user_guide_zh-TW.md`（機器人本體的建立與狀態機）
> **重要**：本版本**不開啟 LIVE 實盤**。`GRID_LIVE_TRADING_ENABLED` 維持關閉，所有操作請在 PAPER 模式進行。

---

## 0. 這兩個功能各自回答什麼問題

| 分頁 | 回答的問題 | 資料來自哪裡 |
|---|---|---|
| **圖表** | 「我這台機器人**實際上**在什麼價位下了什麼單？」 | 引擎心跳快照（真實成交、真實掛單）+ K 線 |
| **回測** | 「這組參數**如果**跑在過去這段行情上，會發生什麼事？」 | 歷史/合成 K 線 + 與實盤同一套決策程式碼的離線回放 |

兩者共用同一張圖表元件與同一套標記語意，所以「回測圖上看到的形狀」與「實盤圖上看到的形狀」意義完全相同。

---

## 1. 圖表分頁

進入「DCA 機器人」→ 點任一台機器人 → 切到 **圖表** 分頁。

### 1.1 圖上有什麼

* **K 線**：來自 `GET /api/v1/market/klines/{symbol}`。已收線的 K 棒由後端提供，**最後一根**會用機器人快照的 `current_price` 在瀏覽器端即時更新（不另開 WebSocket）。
* **標記（marks）**：本機器人自己的下單與成交。
* **價格線（lines）**：入場價、目前均價、止盈價、下一張安全單價、止損價。

### 1.2 標記語意（凍結表，回測與實盤共用）

| 標記 | 形狀 | 顏色 | 位置 | 意義 |
|---|---|---|---|---|
| `base_filled` | 箭頭（多↑／空↓） | 多綠／空紅 | 棒下／棒上 | 基礎單成交＝本輪開倉 |
| `safety_filled` | 圓點 | 多藍／空橘 | 棒下／棒上 | 安全單成交＝攤平了一次 |
| `take_profit_filled` | 箭頭↑ | 綠 | 棒下 | 止盈成交＝本輪結束，文字含**本輪實現報酬 %** |
| `stop_loss_filled` | 箭頭↓ | 紅 | 棒上 | 止損成交 |
| `order_placed` | 空心方塊 | 灰 | 棒內 | **未成交的在世掛單**（僅即時圖，回測不會有） |
| `skipped` | 十字 | 橘 | 棒內 | 該層安全單被略過（例如超出名目上限） |

> **為什麼回測沒有 `order_placed`？** 回測畫的是「這段歷史上實際被撮合的事件」，掛而未成的虛擬訂單在回放結束時沒有意義。即時圖則相反：在世掛單正是你現在最該看到的東西。

### 1.3 三種一定要看懂的角標

| 角標／提示 | 意思 | 你該怎麼做 |
|---|---|---|
| **合成資料** | K 線是 PAPER 模式的**確定性合成序列**，不是真實行情 | 只能用來驗證流程與相對比較，**不可**用來推論真實報酬 |
| **陳舊資料** | 快取中的 K 線超過新鮮度門檻 | 重新整理；持續出現代表回填失敗 |
| **監控中 · 交易所零掛單** | 機器人在 `armed`，尚未進場 | 圖上此時 `order_placed` 標記必為 0，這是正常的，不是壞掉 |

若後端回報 `data_status=unavailable`，畫面會顯示「無法取得 K 線資料」而**不會**畫一張空白圖——空白圖會讓人誤以為市場沒有波動。

### 1.4 未知值不會被畫成 0

價格線的 `price` 為 `null`（例如尚未進場時沒有均價）就**不畫那條線**；`realized_pct` 未知時止盈標記的文字省略百分比，不會顯示 `+0.00%`。看到 0 就代表真的是 0。

## 2. 回測分頁

切到 **回測** 分頁，或在「建立 DCA」精靈的最後一步按「先回測看看」（用**表單當下的參數**跑，不需要先把機器人建出來）。

### 2.1 三個輸入

| 欄位 | 選項 | 說明 |
|---|---|---|
| 時框 | 5m / 15m / 1h / 4h / 1d | 決定一根 K 棒代表多久；時框越大同樣棒數涵蓋的期間越長 |
| 回測長度 | 300 / 1000 / 2000 / 5000 根 | 上限 20000 根，超過會被明確拒絕（不會悄悄截斷） |
| 初始資金 (USD) | 留空＝以階梯所需資金自動帶入 | 影響報酬率分母與最大回撤 |

按「執行回測」後按鈕會禁用並顯示轉圈；按「取消」或切離分頁會中止請求（`AbortController`）。

### 2.2 指標怎麼讀

| 指標 | 讀法 |
|---|---|
| **總報酬 %** | 期末權益相對初始資金的變化 |
| **買入持有報酬 %** | 同一段期間、同一標的**單純持有**的報酬（做空時為反向基準） |
| **超額報酬（alpha）%** | 總報酬 − 買入持有。**這才是「策略有沒有用」的答案**；為負會以警示色顯示，代表你不如什麼都不做 |
| **最大回撤 %** | 權益曲線**峰值到谷底**的最大跌幅（不是頭尾相減） |
| **完成輪次 / 勝率 %** | 完成了幾輪、其中賺錢的比例 |
| **獲利因子** | 總獲利 ÷ 總虧損。**沒有任何虧損輪時顯示「—」而不是 0 或 ∞** |
| **持倉時間占比 %** | 有部位的棒數比例。90% 以上代表資金幾乎一直被鎖住 |
| **已實現損益 / 總手續費** | 直接取自引擎的會計值，與實盤同一口徑 |

> **只看「總報酬為正」就加碼是最常見的誤用。** 空頭段裡買入持有 −12%、策略 −5%，總報酬仍是負的，但 alpha 是 +7%；多頭段裡策略 +3% 而買入持有 +20%，看起來賺錢其實嚴重落後。**永遠先看 alpha。**

### 2.3 六條簡化事項（面板底部常駐顯示）

回測是**理想化**的，以下差異在真實市場一定存在：

1. **不模擬部分成交**：一張單要嘛整張成交、要嘛不成交。真實市場上大單可能只成交一部分。
2. **除跳空外沒有滑價模型**：限價單以限價成交。真實市場有價差與排隊。
3. **未套用交易所最小名目限制**（與實盤路徑的預設一致）：真實下單可能因低於最小名目被拒。
4. **手續費採設定檔的 `fee_rate`**：不含資金費率、不含 VIP 費率階梯。
5. **PAPER 合成 K 線不是真實歷史**：出現「合成資料」角標時，數值只能相對比較。
6. **歷史績效不代表未來**。

這六條會以 API `warnings` 的形式回傳並全量渲染——如果你在畫面上沒看到它們，那是缺陷，請回報。

### 2.4 回測絕對不會下真單

回測是**唯讀**功能：處理期間對交易所的寫入方法呼叫次數為 0，`config/active_dca.json`（熱插拔登記檔）的內容一個位元組都不會變。這兩件事都有自動化測試逐次驗證（`tests/test_dca_chart_backtest_e2e.py`）。

### 2.5 為什麼可以相信回測與實盤一致

回測**沒有第二套模擬器**：它實例化的是真正的 `DcaCoordinator` 與真正的 `DcaOrderExecutor`，只把交易所換成依 K 棒撮合的 `ReplayExchange`。階梯、均價、止盈價、指標全部 import 實盤那份程式碼。

另外兩個關鍵性質：

* **無未来函数**：棒 *i* 送出的訂單最早只能在棒 *i+1* 成交。決策只看得到 ≤ *i* 的資料。
* **同棒保守順序**：一根棒內同時可能攤平又止盈時，先攤平後止盈（不會高估獲利）。

同一組輸入跑兩次，結果逐欄位相同（效能量測 `bars_per_second` 除外）。

## 3. 參數掃描

在回測分頁展開「參數掃描」，對想試的參數給多個值（如止盈 1.0 / 1.5 / 2.0），一次跑完並排比較。

* 表格可依任一指標排序，**最優列會高亮**。
* 表頭固定顯示「共 M 組參數，已完成 N 組」。
* 預算（總棒數／並行數）用完時 `truncated=true`，畫面會明說**只完成了 N/M 組**，且最優列的文案是「**已完成範圍內**的最優」——它**不是**全域最佳解。
* 個別非法組合（例如安全單數為 0）只會讓該列顯示錯誤訊息，不會讓整張表掛掉。

> 掃描是**尋找方向**的工具，不是「自動最佳化」。在一段歷史上最佳的參數，通常只是最貼合那段歷史的參數（過度擬合）。至少換兩段不同期間、不同時框各跑一次再下判斷。

## 4. 常見錯誤訊息

| 訊息 | HTTP | 原因與處理 |
|---|---|---|
| 回測棒數上限為 20000 | 400 / 422 | 減少棒數或改用更大的時框 |
| 不支援的 timeframe | 400 | 只支援 1m/5m/15m/30m/1h/4h/1d |
| 無法取得足夠的 K 線資料 | 400 | 該交易對缺少歷史資料；換交易對或縮短期間 |
| 回測執行逾時，請減少棒數或使用更大的時框 | 408 | 單次回測牆鐘上限 60 秒（掃描 120 秒） |
| 已達寫操作頻率限制 | 429 | 安全護欄；稍候再試 |
| DCA 配置 {bot_id} 不存在 | 404 | 機器人已被刪除或 ID 打錯 |

錯誤一律以紅色提示呈現，**不會**退化成一張看起來正常的空圖表。

## 5. 給工程師：直接打 API

```bash
TOKEN=$(cat .grid_api_token)   # 或使用 GRID_API_TOKEN

# K 線（PAPER 合成，離線可重現）
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8001/api/v1/market/klines/ETH%2FUSDC%3AUSDC?exchange=binance&timeframe=15m&limit=300&account_mode=paper"

# 即時圖表
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8001/api/v1/dca/<bot_id>/chart?timeframe=15m&limit=300"

# 回測
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"bot_id":"<bot_id>","timeframe":"15m","bars":600,"initial_capital":"1000"}' \
  "http://127.0.0.1:8001/api/v1/dca/backtest"

# 參數掃描
curl -s -X POST -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"bot_id":"<bot_id>","timeframe":"15m","bars":400,"take_profit_percent_range":[1.0,1.5,2.0],"best_by":"total_return_pct"}' \
  "http://127.0.0.1:8001/api/v1/dca/backtest/sweep"
```

所有端點都需要 Bearer Token；缺 token 一律 401。回測與掃描都會寫稽核日誌（`run_dca_backtest` / `run_dca_sweep`：誰、何時、對哪個設定跑了回測）。
